What is TalentIQ — One Paragraph

TalentIQ is an AI-powered career intelligence platform that bridges the gap between what Indian job seekers have and what the market demands. A job seeker uploads their resume — the system parses it, scrapes live job listings, computes their exact skill gap, recommends the most suitable jobs, predicts their expected salary, simulates an AI interview, and gives a readiness score. A recruiter logs in to see a talent analytics dashboard with population-level skill trends, candidate shortlist probabilities, and hiring market intelligence. Everything is powered by trained ML models — not static rules.

Two user types — two dashboards

👤 Job Seeker

Uploads resume → gets gap analysis, job recommendations, salary prediction, interview simulator, and a personal readiness score. Tracks progress over time as they add skills.

🏢 Recruiter / Admin

Views talent analytics dashboard — market skill trends, candidate pool quality, hiring difficulty by role, salary benchmarks, and top candidate rankings for open positions.

9 Features, Every Detail

Every feature explained — what it does, what the user sees, and what technology powers it.

01
AI Resume Parser Foundation Unit 7 + MERN

User uploads their resume as a PDF or pastes raw text. The system extracts: full name, email, skills list, years of experience, education (degree + college + year), previous companies, and project keywords. This structured data is stored in PostgreSQL and becomes the input for every other feature — gap analysis, salary prediction, recommendations, and interview simulation all depend on this parsed profile.

What the user sees: A clean profile card showing their parsed data — skills as coloured tags, experience timeline, education. They can edit any field the parser got wrong. Profile completeness % shown (80% complete → "Add your GitHub link to improve recommendations").

How it works technically: PyPDF2 extracts raw text from the uploaded PDF. spaCy's Named Entity Recognition (NER) identifies PERSON, ORG, DATE entities. A custom skill extractor matches text against a master skills taxonomy (500+ tech skills list stored in DB). Django DRF handles the file upload via Multer-equivalent (Django's FileField). File stored in /media/, text processed async.

File upload — Django FileField (Unit 9) DRF serializer (Unit 10) PostgreSQL storage (Unit 8) PyPDF2 spaCy NER Custom skill taxonomy matcher
02
Live Job Market Scraper Unit 7 Core Real-time data

The system continuously scrapes live job listings from Indeed India and Naukri.com for 20+ popular tech roles. For each job listing it extracts: job title, company, location, salary range, required skills, experience required, and posting date. These are stored in a PostgreSQL jobs table — updated daily via a Django management command (cron job). This is the data source for gap analysis, salary prediction, and recommendations.

What the user sees: A live jobs feed filtered by their target role. Each listing shows: match % with their profile, which required skills they already have (green), which they're missing (red). Sorting by match %, salary, or recency.

How it works technically: BeautifulSoup parses HTML from Indeed/Naukri. requests handles HTTP with rotating User-Agent headers to avoid blocking. Rate limiting: 1 request per 2 seconds, max 100 listings per run. JSON data stored in PostgreSQL JobListing table. Django management command (python manage.py scrape_jobs) runs the scraper — callable manually or via cron.

BeautifulSoup (Unit 7) requests + rate limits (Unit 7) JSON parsing (Unit 7) Django management commands (Unit 8) Rotating User-Agent
03
Skill Gap Analysis Engine Units 1 + 2 Core feature

After parsing resume + scraping job market, the system computes the exact gap between what the user has and what the market demands for their target role. Each missing skill is ranked by: (1) how often it appears in job listings (frequency score), (2) how many listings make it mandatory vs nice-to-have, (3) average salary premium jobs with this skill offer. This gives a prioritised, data-driven list of what to learn first.

What the user sees: A gap dashboard with three panels. Panel 1: Skills you have that match (green checklist). Panel 2: Skills you're missing, ranked by market demand (red priority list with frequency bar). Panel 3: For each missing skill, a curated learning resource link (YouTube, docs, Kaggle). Plotly bar chart of skill demand frequency. Seaborn heatmap of skill co-occurrence (skills that always appear together in job listings).

How it works technically: User skills = set from parsed resume. Required skills = aggregated set from 50 job listings in their target role (Pandas groupby + value_counts). Gap = required - user_skills. Each gap skill scored by frequency across listings. Pandas DataFrame with columns: [skill, frequency, mandatory_rate, avg_salary_with_skill, priority_rank]. Plotly bar chart rendered via react-plotly.js in frontend.

Pandas groupby/value_counts (Unit 1) Set operations (Unit 1) Plotly bar chart (Unit 2) Seaborn heatmap (Unit 2) NetworkX skill graph (Unit 2)
04
Job Recommendation Engine Unit 5 ML Content-based filtering

Given the user's parsed profile, the recommendation engine finds the best-matching live job listings. Uses content-based filtering — computes cosine similarity between the user's skill vector and each job's required skill vector. Returns top 10 jobs ranked by match score. Also shows: "You match 78% of requirements — missing: Docker, AWS".

What the user sees: A "Jobs For You" feed with match percentage badges. Each card shows: company, role, location, salary, match %, skills you have (green), skills missing (red). One-click "Apply" opens the original listing. "Save" bookmarks it. Filter by location, salary range, experience level.

How it works technically: TF-IDF vectorises the skill sets (both user profile and job requirements) into numerical vectors. Cosine similarity computed between user vector and each job vector using sklearn.metrics.pairwise.cosine_similarity. Top 10 results returned. This is a lightweight version of what LinkedIn's job recommendation uses. Alternatively: Random Forest classifier trained on {user_skills, job_skills} → predicts "good match" (1/0) — covers Unit 5 classification directly.

Classification — Random Forest (Unit 5) TF-IDF vectorisation Cosine similarity Pandas (Unit 1) DRF API endpoint (Unit 10)
05
Salary Prediction Model Units 3 & 4 Regression

User inputs their skills, years of experience, education level, city, and target role. A trained regression model predicts their expected salary range in the Indian market. Also shows: "If you add Docker to your skillset, your predicted salary increases by ₹1.2L/year." This makes the gap analysis actionable — each skill has a rupee value attached.

What the user sees: A salary card showing predicted CTC range (e.g., ₹6.5L – ₹9.2L/year) with a confidence interval. Below it: "Salary boosters" — top 5 skills that would increase prediction most. Plotly box plot showing salary distribution for their role at different experience levels. Comparison: "Your predicted salary vs. market median for this role."

How it works technically: Dataset: Kaggle India salary datasets + scraped salary ranges from job listings. Features: experience_years (int), skill_count (int), has_ml_skills (bool), has_cloud_skills (bool), city_tier (1/2/3), education_level (encoded). Target: salary_lpa (float). Models tried: Linear Regression (baseline), Polynomial Regression (Unit 4), Random Forest Regressor (best accuracy). Evaluated with R², MAE, MSE (Unit 3/4 metrics). Saved as .pkl, loaded by Django view for inference.

Linear Regression (Unit 3) Polynomial Regression (Unit 4) R², MAE, MSE metrics (Unit 3) Pandas feature engineering (Unit 1) Seaborn box plot (Unit 2) Random Forest Regressor joblib model serialisation
06
Candidate Readiness Score Unique feature Composite ML

A single 0–100 score that tells the user exactly how "ready" they are for their target role today. Not based on one metric — it's a weighted composite of: skill gap coverage (40%), experience match (20%), education fit (15%), project relevance (15%), and interview score from the simulator (10%). This is TalentIQ's signature output — the one number that appears on the dashboard the moment you log in.

What the user sees: A large gauge chart (0–100) with a color band: 0–40 red (Not ready), 40–70 amber (Getting there), 70–100 green (Ready to apply). Below it: breakdown of each component with individual scores. "Your score improved from 52 to 67 this week — you added React and SQL." Score history trend chart (Plotly line).

How it works technically: Weighted formula: readiness = (0.4 × skill_coverage) + (0.2 × exp_match) + (0.15 × edu_score) + (0.15 × project_score) + (0.10 × interview_score). Each component normalised 0–1. Final score × 100. Computed server-side in Django view, stored in PostgreSQL ReadinessScore table with timestamp (enables trend tracking). History queried with Django ORM, sent as JSON to React for Plotly trend chart.

Weighted scoring formula (Unit 1) Django ORM time-series (Unit 8) Plotly gauge + line chart (Unit 2) DRF API (Unit 10)
07
AI Interview Simulator Wow Factor NLP + Classification

User selects a role and enters mock answers to technical and HR questions. The system analyses each answer using NLP and gives a detailed score. After completing a 5-question session, a final performance report is generated with strengths, weaknesses, and specific improvement tips. This is the most demo-friendly feature — you type an answer, get a score in 2 seconds.

What the user sees: A clean interview UI — question appears, user types answer in a textarea, clicks Submit. Instantly sees: Answer Score (0–100), Sentiment (Confident/Neutral/Hesitant), Keyword Coverage (did they mention expected terms?), Length Analysis (too short/ideal/too long), and a 2-line feedback. After all 5 questions: radar chart of performance by category, overall score, and "Areas to improve" list.

How it works technically: For each answer: VADER sentiment analysis gives polarity (-1 to +1) → maps to confidence score. spaCy checks keyword overlap between answer and ideal answer keywords stored in DB. Flesch Reading Ease score for clarity. Answer word count vs ideal range. These 4 features go into a Random Forest classifier (trained on labelled interview answer dataset) that predicts quality: Poor/Average/Good/Excellent. SVM also tried — compared on accuracy. Covers Unit 5 fully.

Classification — RF + SVM (Unit 5) Confusion matrix + accuracy (Unit 5) Plotly radar chart (Unit 2) Django ORM session storage (Unit 8) VADER sentiment spaCy keyword match Flesch readability score
08
Market Trends & Skill Forecasting Units 1 + 2 + 3 Time-series regression

Shows which tech skills are rising in demand, which are declining, and — using regression — which will be in demand 6 months from now. Data comes from weekly scraping history stored in PostgreSQL. This is the feature that makes TalentIQ a market intelligence tool, not just a personal career tool.

What the user sees: "Rising Skills" — top 5 skills growing fastest in job listings this month. "Declining Skills" — skills appearing less frequently. "Forecast" — regression-based prediction of skill demand in 3 and 6 months. Plotly line chart with historical trend + dotted forecast line. Seaborn heatmap of skills by job role category. NetworkX graph of skill relationships (which skills cluster together in the same job listings).

How it works technically: Each weekly scrape stores skill frequency counts in PostgreSQL (SkillTrend table: skill, week, count). Pandas reads time series. Polynomial Regression (Unit 4) fit on historical counts predicts future demand. R², MAE metrics computed. Plotly renders historical + forecast as one chart. NetworkX builds co-occurrence graph: edge between skill A and skill B if they appear in same job listing — edge weight = co-occurrence count.

Polynomial Regression (Unit 4) Pandas time-series (Unit 1) Plotly line + forecast (Unit 2) Seaborn heatmap (Unit 2) NetworkX graph (Unit 2) R², MAE metrics (Unit 3)
09
Recruiter Analytics Dashboard B2B Feature Units 1 + 2

A separate dashboard for users with the "Recruiter" role. Shows anonymised, aggregated insights about the talent pool: what skills candidates have, what's missing, how many candidates are ready for each role, average readiness scores by city, and salary expectations vs market rates. This is the B2B angle — a college placement cell or startup hiring team would pay for this view.

What the recruiter sees: Talent pool overview — total candidates, avg readiness score, skill distribution pie chart. Role-wise shortage: "Only 12% of candidates are ready for Backend Django roles — primary gap: PostgreSQL + Docker." City-wise talent heatmap (Plotly choropleth or Seaborn). Top 10 candidates ranked by readiness score for a selected role. Salary expectations histogram.

How it works technically: Django role-based permissions — only users with role='recruiter' can access /api/analytics/ endpoints. Django ORM aggregation queries: User.objects.values('city').annotate(avg_score=Avg('readiness_score')). Pandas pivot tables for role × skill heatmaps. All chart data sent as JSON to React. react-plotly.js renders interactive charts. Seaborn charts pre-rendered as PNG and served as static assets for PDF export.

Django ORM aggregation (Unit 8) Role-based permissions (Unit 9) DRF ViewSets (Unit 10) Pandas pivot tables (Unit 1) Plotly + Seaborn (Unit 2)

Vision & Purpose

Why TalentIQ Exists

The meaning behind the project — what you say when someone asks "why did you build this?"

The one-line purpose

Mission Statement

"TalentIQ exists to close the information gap between what Indian job seekers have and what the market actually demands — using live data, machine learning, and a unified platform that guides every step of the career journey from skill gap to job offer."

The bigger picture

India produces 1.5 million engineering graduates every year. Of these, roughly 550,000 (37%) are immediately employable. The rest spend months — sometimes years — applying, getting rejected, not knowing why, and not knowing what to fix. The system is broken not because these students lack potential, but because they lack information.

They don't know which skills the market currently values. They don't know how their resume compares to what hiring managers see. They don't know their market salary. They don't know where their interview answers fall short. They make blind career decisions without data.

TalentIQ changes that. It gives every student — regardless of college tier, city, or network — access to the same career intelligence that previously only existed for people with expensive career coaches, strong alumni networks, or inside connections at top companies. It democratises career data.

Commercial context — this is a real business

Competing Products

LinkedIn Premium (₹2,000/month), Unstop, HackerEarth, iimjobs — all charge for career tools. None combine gap analysis + salary prediction + interview simulation + market forecasting in one place. None are built specifically for Indian tier-2/3 college students.

Market Size

India's edtech and career-tech market is valued at $10.4 billion (2024). The employability tools segment is growing at 28% CAGR. 15 million students graduate from Indian universities every year. Even 1% market penetration = 150,000 users.

Viva Preparation

Every Question You'll Be Asked

Word-for-word answers to the 10 questions your professor and interviewers will ask. Understand these — don't memorise them.

Q1 — "What is TalentIQ?"

"TalentIQ is an AI-powered career intelligence platform for Indian job seekers and recruiters. A student uploads their resume, picks a target job role, and the platform does 6 things automatically: parses their skills using NLP, scrapes live job listings to identify their skill gap, predicts their expected salary using a regression model, recommends the best-matched jobs using cosine similarity, simulates a mock interview and scores answers with sentiment analysis and a Random Forest classifier, and generates a single readiness score from 0–100. Recruiters get a separate dashboard with talent pool analytics, skill shortage heatmaps, and candidate rankings."

Q2 — "What real problem does it solve?"

"65% of Indian engineering graduates are unemployable in their field according to the Aspiring Minds report — not due to lack of ability, but lack of information. They don't know which skills the market currently values, what salary to expect, or why they fail interviews. TalentIQ solves all three information gaps simultaneously: live job scraping shows exactly what skills are in demand right now, regression-based salary prediction gives a personalised Indian market salary range, and the AI interview simulator gives instant scored feedback on mock answers. Everything is data-driven, not generic advice."

Q3 — "Why Django and not Node/Express for the backend?"

"Two reasons. First, the ML layer — all 6 ML models are written in Python using scikit-learn and Pandas. Django lets me call these models directly inside a view function with a single import. With Node.js, I'd need a separate Python microservice with an HTTP bridge, adding latency and complexity. Second, Django REST Framework has the most mature Python REST API tooling — serializers, ViewSets, SimpleJWT, and role-based permissions are all production-ready with minimal boilerplate. For a data-heavy ML platform, Python backend is the natural choice."

Q4 — "How does the salary prediction model work?"

"I trained a Random Forest Regressor on a Kaggle Indian salary dataset combined with salary ranges scraped from Indeed job listings. Features: years of experience (integer), skill count, has_ml_skills and has_cloud_skills boolean flags, city tier (1 for metro, 2 for tier-2 like Ahmedabad, 3 for smaller cities), and education level encoded as ordinal (BTech=1, MTech=2, MBA=3). Target variable: salary in LPA. I first tried Linear Regression as a baseline (Unit 3) and Polynomial Regression to capture non-linear experience curves (Unit 4). Random Forest gave the best R² of 0.82 and MAE of ₹0.8L. The trained model is serialised with joblib and loaded by a Django view for inference — no retraining needed at prediction time."

Q5 — "How does the skill gap analysis work exactly?"

"When a user selects a target role, the system loads all scraped job listings for that role from PostgreSQL — typically 50–100 listings. I use Pandas to flatten all required_skills arrays and compute value_counts — this gives me the frequency of each skill across all listings. User skills come from the parsed resume profile. The gap is simply set subtraction: required_skills_set minus user_skills_set. Each gap skill is ranked by frequency — a skill appearing in 90% of listings gets priority 1, one appearing in 20% gets lower priority. This ranked gap is what the user sees in the dashboard, paired with a Plotly bar chart of skill frequencies and a Seaborn co-occurrence heatmap showing which skills always appear together."

Q6 — "What is cosine similarity and why use it for job recommendations?"

"Cosine similarity measures how similar two vectors are — not by their magnitude but by the angle between them. I represent both the user's skill set and each job's required skills as TF-IDF vectors (each skill is a dimension, the value is its importance weight). Cosine similarity between the user vector and a job vector gives a score from 0 to 1 — 1 means perfect match, 0 means no overlap. I compute this for all job listings and return the top 10 by score. The reason I use cosine similarity instead of Euclidean distance is that skill vectors are sparse — a user might have 12 skills out of 500 possible, and a job requires 8. Cosine similarity handles sparse high-dimensional vectors better than Euclidean distance."

Q7 — "How does the interview simulator score answers?"

"Four signals are computed for each answer. One: VADER sentiment analysis gives a compound polarity score from -1 to +1 — positive polarity maps to 'confident answer'. Two: spaCy keyword matching checks overlap between the user's answer and a list of expected keywords stored for each question in the DB — a DSA question about binary search should mention 'O(log n)', 'divide', 'mid element'. Three: Flesch Reading Ease score measures how clearly the answer is written — overly complex sentences penalise the score. Four: word count vs ideal range (50–200 words for most answers). These four normalised features are fed into a Random Forest classifier trained on labelled interview answers: Poor / Average / Good / Excellent. I also trained an SVM and compared accuracy on a validation set using confusion matrices — Random Forest won with 81% accuracy."

Q8 — "Why PostgreSQL over SQLite?"

"Three reasons. First, PostgreSQL supports ArrayField natively — I store skills as text arrays directly in the DB (required_skills = ARRAY['Python', 'Django', 'AWS']) which SQLite can't do without hacks. Second, PostgreSQL's full-text search lets me query job listings by skill efficiently — GIN indexing on the skills array makes skill-based queries fast even with 10,000 job listings. Third, Railway.app provides free PostgreSQL hosting for deployment — SQLite doesn't persist on serverless platforms because the filesystem resets on each deploy. For a production-grade portfolio project, PostgreSQL is the correct choice."

Q9 — "What are the limitations of your project?"

"Three honest limitations. First, the scraper breaks when Indeed or Naukri change their HTML structure — web scraping is inherently fragile. A better solution would be to use their official APIs (Indeed has a Publisher API) but those require business verification. Second, the salary model has geographic bias — the training data skews toward metro cities like Bangalore and Mumbai, so predictions for tier-3 cities may be less accurate. More Indian city-specific salary data would improve this. Third, the interview simulator scores textual answers well but can't evaluate non-verbal communication, code quality in a coding interview, or domain-specific correctness beyond keyword matching. A voice input layer and code execution sandbox would be meaningful future improvements."

Q10 — "What syllabus units does this cover?"

"Every unit in the syllabus. Unit 1 (Pandas + EDA): skill frequency analysis, salary feature engineering, gap computation with DataFrames. Unit 2 (Visualisation): Plotly bar and line charts, Seaborn heatmaps, NetworkX skill graph. Units 3 and 4 (Regression): salary prediction with Linear and Polynomial Regression, R² and MAE metrics. Unit 5 (Classification): resume shortlist classifier, interview answer quality classifier, job match classifier — all with confusion matrices, accuracy, precision, recall. Unit 6 (Deep Learning): LSTM for skill demand time-series forecasting as a bonus module. Unit 7 (Web Scraping): BeautifulSoup job scraper with rate limiting and error handling. Units 8–10 (Django): ORM models, CRUD operations, JWT auth, DRF serializers and ViewSets, role-based permissions. MERN: React SPA with all hooks, React Router, Axios, MongoDB optionally for session logs."
