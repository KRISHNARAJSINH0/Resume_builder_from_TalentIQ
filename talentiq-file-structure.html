Production-Grade · Monorepo

TalentIQ — Complete File Structure

Full production-grade monorepo. Django backend + React frontend + ML models + config files. Every file has a purpose. Nothing is filler.

How to read this structure

The project lives in one root folder called talentiq/. Inside: backend/ (Django), frontend/ (React), ml/ (Jupyter notebooks + trained models), and docker/ + config files at root. Each Django app is one feature. Each React page is one screen. ML models are .pkl files served by Django views.

Django Structure Deep Dive

Backend — Every App Explained

9 Django apps. Each app owns exactly one feature. Each has the same structure: models → serializers → views → urls → business logic file.

The "one app per feature" rule

Why separate apps instead of one big app?

Each Django app is independently testable, independently deployable (if you ever split to microservices), and maps cleanly to one DRF router prefix. When your professor opens the code, they immediately see: accounts/ = auth, resume/ = parsing, jobs/ = scraping, gap_analysis/ = ML gap, salary/ = ML salary, interview/ = ML interview, readiness/ = composite score, analytics/ = recruiter, notifications/ = email. Clean separation = professional code = better viva marks.

Business logic files — what goes where
FileAppWhat It Contains
parser.pyresume/PyPDF2 text extraction + spaCy NER pipeline. Input: PDF file path. Output: dict of {name, skills, experience, education, companies}
skill_extractor.pyresume/Loads master skills taxonomy (500+ skills list from DB). Matches parsed text against taxonomy. Returns ranked list of confirmed skills.
base_scraper.pyjobs/scrapers/Base class with rate limiting (time.sleep), retry logic (3 attempts), rotating User-Agent headers, request error handling. All scrapers inherit this.
indeed_scraper.pyjobs/scrapers/BeautifulSoup parser for Indeed India. Extracts: title, company, salary, skills from JD, location, experience. Saves to JobListing model.
engine.pygap_analysis/Core Pandas gap logic. Loads jobs for target role → flattens skills → value_counts → set diff with user skills → returns ranked gap DataFrame.
chart_builder.pygap_analysis/Plotly bar chart JSON for gap. Seaborn heatmap PNG for skill correlation. NetworkX graph JSON for skill relationships. Returns JSON/base64 strings.
engine.pyrecommendations/TF-IDF vectorises user skills + job skill sets. sklearn cosine_similarity. Returns top-10 job IDs with match scores.
predictor.pysalary/Loads salary_rf_model.pkl with joblib. Builds feature array from user profile. Returns predicted salary range with confidence interval.
scorer.pyinterview/VADER sentiment → polarity score. spaCy keyword overlap. Flesch readability. Word count analysis. RF classifier inference. Returns quality label + per-metric scores.
calculator.pyreadiness/Queries gap coverage %, interview session avg score, exp match %, edu level score. Applies weighted formula. Saves ReadinessScore row. Returns 0–100.
forecaster.pyanalytics/Reads SkillTrend time series from DB. Fits Polynomial Regression per skill. Predicts demand in 4, 8, 12 weeks. Returns forecast dict with confidence.

Every Important File — What It Does

Quick reference for every non-obvious file in the project. If you know what a file does, you can explain it in a viva.

Django backend — key files
File PathWhat It DoesWhy It Exists
config/settings/base.pyAll shared Django settings — INSTALLED_APPS, MIDDLEWARE, REST_FRAMEWORK config, JWT settings, CORSSplit settings prevent dev config leaking into production
config/settings/production.pyOverrides: DEBUG=False, ALLOWED_HOSTS=Railway domain, STATIC_ROOT, database from DATABASE_URL env varProduction needs different security settings than local dev
accounts/signals.pyDjango signal: when a User is created → auto-create a UserProfile for them with default role='seeker'Every User automatically gets a Profile — no manual creation needed
accounts/permissions.pyCustom DRF permission classes: IsSeeker (role=='seeker'), IsRecruiter (role=='recruiter'), IsOwner (obj.user==request.user)Role-based access control — recruiter can't access seeker endpoints and vice versa
jobs/scrapers/base_scraper.pyAbstract base class with: rate_limit() method (time.sleep), retry_request() with 3 attempts + backoff, rotating User-Agent list, error loggingDRY principle — both Indeed and Naukri scrapers inherit this so rate limiting is not duplicated
jobs/management/commands/scrape_jobs.pypython manage.py scrape_jobs — runs both scrapers, saves results to DB, logs count of new listings addedManagement commands run independently of the web server — can be scheduled via cron or Railway cron job
gap_analysis/engine.pyTakes (user_skills: list, target_role: str) → loads job listings from DB → Pandas operations → returns ranked gap DataFrame as dictBusiness logic separated from Django view — testable independently, reusable by other views
salary/predictor.pyOn startup, loads salary_rf_model.pkl with joblib into module-level variable (one load, not per-request). predict(features) method runs inference.Loading .pkl on every request would be slow. Module-level loading means it's loaded once when Django starts.
interview/scorer.pyPipeline: text → VADER sentiment → spaCy keyword match → Flesch score → word count → feature array → RF.predict() → quality label + individual scoresAll scoring logic in one place — unit testable, not mixed into view code
readiness/calculator.pyQueries all component scores for user → applies weighted formula → creates ReadinessScore DB row → returns score dictSaves score to DB on every computation to enable historical trend chart
analytics/networkx_builder.pyLoads all job listings → builds co-occurrence matrix (which skills appear together) → creates NetworkX graph → exports as JSON for ReactNetworkX graph shows which skills cluster together — recruiter insight that's not available anywhere else
core/exceptions.pyCustom DRF exception handler — returns consistent JSON error format: {error: "message", code: "ERROR_CODE", status: 400}Without this, DRF returns different error formats for different error types — inconsistent for React to handle
React frontend — key files
File PathWhat It DoesWhy It Exists
api/axiosConfig.jsCreates axios instance with baseURL from env. Request interceptor: adds Authorization header. Response interceptor: catches 401 → calls refresh token → retries original request.Without this, every component would manually add auth headers. Interceptors do it automatically for every request.
context/AuthContext.jsxStores token + user + role in React state. Provides login(token), logout(), isAuthenticated. Wraps entire app so any component can access auth state.Global auth state that any component can access without prop drilling 5 levels deep.
components/common/PrivateRoute.jsxChecks if user is authenticated AND has correct role. If not → redirects to /login. Wraps all protected routes in App.jsx.Without this, anyone could navigate to /dashboard by typing the URL directly.
hooks/useInterview.jsManages interview session as state machine: idle → started → question_1 → question_2 → ... → completed. Handles API calls for start/submit/next question.Interview has complex state transitions — custom hook keeps all this logic out of the component.
components/charts/ReadinessGauge.jsxPlotly gauge chart (0–100) with color zones: red (0–40), amber (40–70), green (70–100). Receives score as prop, renders via react-plotly.js.The signature visual of TalentIQ — appears on dashboard and is the first thing users see.
layouts/SeekerLayout.jsxRenders sidebar with seeker nav links + topbar with user name + notification bell. All seeker pages render inside this layout's Outlet.Consistent layout across all seeker screens without duplicating Navbar in every page component.
utils/constants.jsROLES = {SEEKER, RECRUITER}. SKILL_CATEGORIES = [Frontend, Backend, ML, DevOps...]. CITY_TIERS = {Metro: 1, Tier2: 2}.Magic strings scattered everywhere cause bugs. Constants in one place are easy to update.
